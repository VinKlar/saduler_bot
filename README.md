# UIB Bot

## Актуальный сценарий выбора группы (2026–2027)

Новый пользователь больше не выбирает институт или факультет. После запуска бот
предлагает один из двух способов регистрации:

1. Ввести код и название направления, например `09.03.03 Прикладная информатика`,
   затем выбрать профиль, форму обучения и группу кнопками.
2. Сразу ввести группу, например `8101` или `1122 э`.

Каталог направлений, профилей и 310 групп хранится в
`bot/group_catalog.json` и собирается из таблицы 2026–2027 командой:

```powershell
python scheduler/build_group_catalog.py `
  "scheduler/МАХ-Профили_актуальные-26-27 у.г..xlsx" `
  "bot/group_catalog.json"
```

Группы с отсутствующим локальным расписанием можно зарегистрировать, но при
запросе расписания бот сообщает, что данные пока не загружены. Чужое расписание
в качестве значения по умолчанию больше не подставляется.

Бот расписания для платформы MAX. Проект получает события через long polling, обрабатывает сообщения и нажатия inline-кнопок, сохраняет выбранную пользователем группу и отправляет ответы по заранее описанным JSON-сценариям.

## Возможности

- запуск бота по токену MAX из `.env`;
- получение обновлений через `GET /updates`;
- отправка сообщений через `POST /messages`;
- маршрутизация входящих событий по сообщениям, командам, callback-кнопкам и состояниям пользователя;
- первичная регистрация пользователя: выбор направления, затем выбор группы;
- сохранение выбранной группы в `users/users.json`;
- отправка клавиатур из JSON-файлов `bot/scen.json` и `bot/buttons_groups.json`;
- базовые ответы на кнопки/сообщения "Сегодня" и "Завтра";
- fallback-обработчики для неизвестных сообщений и неизвестных кнопок.

## Требования

- Python 3.10 или новее;
- зарегистрированный бот в MAX;
- токен бота для MAX API;
- зависимости Python:
  - `httpx`;
  - `python-dotenv`.

## Установка

1. Создайте и активируйте виртуальное окружение:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

2. Установите зависимости:

```powershell
pip install httpx python-dotenv
```

3. Создайте файл `.env` в корне проекта:

```env
MAX_TOKEN=ваш_токен_бота
```

4. Проверьте, что файл `users/users.json` существует и содержит валидный JSON:

```json
{}
```

## Запуск

Из корня проекта выполните:

```powershell
python main.py
```

После запуска бот выводит сообщение в консоль и начинает бесконечный цикл получения обновлений. При ошибке цикл не падает окончательно: ошибка печатается в консоль, затем бот ждёт 5 секунд и продолжает работу.

## Как работает бот

### 1. Получение обновлений

`main.py` вызывает `get_updates(marker)`, который обращается к:

```text
https://platform-api.max.ru/updates
```

Параметры запроса:

- `limit=100` - максимальное количество обновлений за один запрос;
- `timeout=30` - ожидание новых событий на стороне API;
- `marker` - позиция следующего чтения, чтобы не обрабатывать старые события повторно.

Каждое обновление передаётся в `handle_update(update)`.

### 2. Контекст приложения

Для каждого обновления создаётся общий `context`:

```python
context = {
    "USERS": USERS,
    "USER_STATE": USER_STATE,
    "save_users": save_users,
}
```

Назначение полей:

- `USERS` - данные из `users/users.json`;
- `USER_STATE` - временные состояния пользователей в памяти процесса;
- `save_users` - функция сохранения `USERS` обратно в JSON-файл.

Важно: `USER_STATE` хранится только в памяти. После перезапуска бота незавершённый выбор направления/группы будет потерян.

### 3. Разбор события

Класс `Event` в `bot/router.py` приводит разные типы обновлений MAX к единому виду:

- `message_created` превращается в событие `message`;
- `message_callback` превращается в событие `callback`;
- `bot_started` превращается в событие `bot_started`;
- неизвестные типы игнорируются.

У события могут быть заполнены:

- `event.type`;
- `event.user_id`;
- `event.chat_id`;
- `event.text`;
- `event.payload`.

### 4. Маршрутизация

`Router.dispatch()` ищет подходящий обработчик в таком порядке:

1. обработчик текущего состояния пользователя;
2. обработчик запуска бота;
3. обработчик команды, если текст начинается с `/`;
4. обработчик обычного сообщения;
5. обработчик callback-кнопки.

Состояние имеет приоритет над обычными сообщениями и кнопками. Это нужно, чтобы пользователь в процессе регистрации сначала выбрал направление, потом группу.

## Пользовательский сценарий

### Новый пользователь

1. Пользователь отправляет `/start`.
2. Если его `user_id` отсутствует в `users/users.json`, бот переводит его в состояние `WAIT_DIRECTION`.
3. Бот отправляет клавиатуру направлений из сценария `group`.
4. Пользователь нажимает направление.
5. Бот переводит пользователя в состояние `WAIT_GROUP`.
6. Бот отправляет клавиатуру групп из `bot/buttons_groups.json` по выбранному направлению.
7. Пользователь нажимает группу.
8. Бот сохраняет:

```json
{
  "user_id": {
    "group": "payload выбранной группы"
  }
}
```

9. Состояние пользователя удаляется из `USER_STATE`.
10. Бот отправляет сообщение о сохранении группы и основную клавиатуру.

### Уже зарегистрированный пользователь

Если пользователь уже есть в `users/users.json`, обработчик `/start` сразу отправляет основной сценарий `/start` из `bot/scen.json`.

## Обработчики

Основные обработчики находятся в `bot/handlers.py`.

### Сообщения

```python
@router.message("/start")
async def start_handler(event, context):
    ...
```

Обработчик с точным текстом сообщения. Сейчас `/start` зарегистрирован именно как message handler, а не через `@router.command("start")`.

```python
@router.message("Сегодня")
async def today_handler(event, context):
    ...
```

Отвечает на текстовое сообщение "Сегодня".

```python
@router.message()
async def unknown_message_handler(event, context):
    ...
```

Fallback для всех сообщений, которые не подошли под более точные обработчики.

### Callback-кнопки

```python
@router.callback("today")
async def today_callback_handler(event, context):
    ...
```

Обработчик кнопки с payload `today`.

```python
@router.callback()
async def unknown_callback_handler(event, context):
    ...
```

Fallback для неизвестных callback-кнопок.

### Состояния

```python
@router.state("WAIT_DIRECTION")
async def wait_direction_handler(event, context):
    ...
```

Ожидает выбор направления.

```python
@router.state("WAIT_GROUP")
async def wait_group_handler(event, context):
    ...
```

Ожидает выбор группы и сохраняет пользователя.

## JSON-сценарии сообщений

Сообщения и клавиатуры описываются в JSON, а `bot/conveyor.py` превращает их в payload для MAX API.

### `bot/scen.json`

Содержит общие сценарии:

- `/start` - приветствие и основная клавиатура;
- `push_button` - универсальный ответ с основной клавиатурой;
- `group` - клавиатура выбора направления.

Пример структуры:

```json
{
  "push_button": {
    "text": "{text}",
    "buttons": [
      [
        {
          "type": "callback",
          "text": "Сегодня",
          "payload": "today"
        }
      ]
    ]
  }
}
```

Поле `text` может содержать шаблон `{text}`. Значение подставляется из аргумента `text` при вызове `send_message()`.

### `bot/buttons_groups.json`

Содержит группы для каждого направления. Ключ верхнего уровня должен совпадать с `payload` кнопки направления из `bot/scen.json`.

Пример связи:

```json
{
  "35.03.04 Агрономия": {
    "text": "35.03.04 Агрономия",
    "buttons": [
      [
        {
          "type": "callback",
          "text": "1101",
          "payload": "1101"
        }
      ]
    ]
  }
}
```

Когда пользователь выбирает направление, его `payload` используется как ключ:

```python
tmp_scen = copy.deepcopy(GROUPS[scen])
```

Если ключа нет в `buttons_groups.json`, отправка завершится ошибкой `KeyError`.

## Отправка сообщений

Для отправки используется функция:

```python
await send_message(chat_id, scen, **data)
```

Аргументы:

- `chat_id` - идентификатор чата MAX;
- `scen` - ключ сценария в `bot/scen.json` или `bot/buttons_groups.json`;
- `text` - текст для подстановки в шаблон `{text}`;
- `ch_g=True` - брать сценарий из `buttons_groups.json`, а не из `scen.json`.

Примеры:

```python
await send_message(event.chat_id, "/start")
```

```python
await send_message(
    event.chat_id,
    "push_button",
    text="Расписание на сегодня"
)
```

```python
await send_message(
    event.chat_id,
    event.payload,
    text="Группа",
    ch_g=True
)
```

## Как добавить новое сообщение

1. Добавьте сценарий в `bot/scen.json`:

```json
{
  "help": {
    "text": "Список доступных действий",
    "buttons": []
  }
}
```

2. Добавьте обработчик в `bot/handlers.py`:

```python
@router.message("Помощь")
async def help_handler(event, context):
    await send_message(event.chat_id, "help")
```

Если нужна кнопка, добавьте её в нужный сценарий:

```json
{
  "type": "callback",
  "text": "Помощь",
  "payload": "help"
}
```

И обработчик callback:

```python
@router.callback("help")
async def help_callback_handler(event, context):
    await send_message(event.chat_id, "help")
```

## Как добавить направление и группы

1. В `bot/scen.json` добавьте кнопку направления в сценарий `group`:

```json
{
  "type": "callback",
  "text": "01.02.03 Новое направление",
  "payload": "01.02.03 Новое направление"
}
```

2. В `bot/buttons_groups.json` добавьте объект с таким же ключом:

```json
{
  "01.02.03 Новое направление": {
    "text": "01.02.03 Новое направление",
    "buttons": [
      [
        {
          "type": "callback",
          "text": "101",
          "payload": "101"
        }
      ]
    ]
  }
}
```

Ключ в `buttons_groups.json` и `payload` кнопки направления должны совпадать полностью, включая пробелы.

## Формат `users/users.json`

Файл используется как простое локальное хранилище:

```json
{
  "123456789": {
    "group": "1101"
  }
}
```

Ключ - `user_id` пользователя MAX, преобразованный в строку. Значение `group` - payload выбранной группы.

## Важные замечания

- Токен не должен попадать в Git. Файл `.env` уже добавлен в `.gitignore`.
- `users/users.json` содержит пользовательские данные. Если проект будет использоваться в продакшене, стоит продумать резервное копирование и защиту файла.
- `USER_STATE` не сохраняется между перезапусками.
- Сейчас ответы "Сегодня" и "Завтра" являются заглушками: они отправляют текст "Расписание на сегодня/завтра", но не загружают реальное расписание из внешнего источника.
- В коде нет отдельного `requirements.txt`. Если проект будут разворачивать на другой машине, его удобно добавить.
- В JSON-файлах и некоторых строках кода сейчас видны некорректно декодированные русские символы. Перед наполнением реальным контентом стоит привести файлы к нормальной UTF-8 кодировке.
